# L’Antica Forno Médéa — واجهة الزبون + Supabase

**الحالة:** مشروع كامل: واجهة الزبون `index.html` + لوحة `admin.html` (الطلبات، المنتجات والأحجام والإضافات وخيارات الصلصة/النوع، التصنيفات، مناطق التوصيل، الأوقات والإعدادات والصور) + قاعدة البيانات.

## الإعداد
1. أنشئ مشروعًا في Supabase، ثم SQL Editor: شغّل `supabase/schema.sql` ثم `supabase/seed.sql` (قائمة الطعام والأسعار والمناطق الحقيقية من ملفك).
2. Authentication ← Sign In / Providers: **عطّل "Allow new users to sign up"**. أنشئ مستخدم المدير يدويًا (Users ← Add user)، ثم شغّل:
   `insert into public.admins(user_id) select id from auth.users where email = 'بريدك@example.com';`
3. عدّل `js/supabase-config.js` بـ Project URL و anon/publishable key فقط (لا تضع service_role أبدًا).
4. GitHub Pages: ارفع كل الملفات إلى مستودع، ثم Settings ← Pages ← Branch: main / root.

## الأمان
- الزبون لا يملك أي صلاحية قراءة/تعديل/حذف على `orders`؛ يستطيع فقط استدعاء الدالة `place_order`.
- الدالة تعيد حساب الأسعار والإجمالي ورسوم التوصيل من قاعدة البيانات، وتتحقق من أوقات العمل والطاولة والهاتف، وتحدّ من تكرار الطلبات (5 كل 10 دقائق لكل هاتف).
- لمنع الطلبات الآلية المكثفة ستحتاج لاحقًا إلى Cloudflare Turnstile أو ما يماثله؛ الحد الحالي بسيط.

## اختبار بعد النشر
اطلب توصيلًا واستلامًا وطلبًا داخل المطعم، وتأكد أن كل طلب يظهر في `orders` بالإجمالي الصحيح، وأن فصل الإنترنت أثناء التأكيد يُبقي السلة.

## ملاحظات
- Supabase المجاني يوقف المشروع بعد أسبوع بلا نشاط؛ إن توقف شغّله من لوحة Supabase.
- يفضّل فتح `admin.html` عبر رابط GitHub Pages نفسه، وعدم مشاركة رابطه (الحماية الفعلية هي تسجيل الدخول وسياسات RLS لا إخفاء الرابط).
